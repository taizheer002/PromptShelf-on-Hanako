# PromptShelf on HanaAgent 设计文档

- 日期：2026-08-15
- 状态：v3（用户已批准）
- 类型：HanaAgent 社区插件（UI + Agent 工具）
- 形态：`full-access`，widget（右侧侧栏）+ tools + routes（**第一版无 page 全屏页**）

## 1. 概述与定位

个人全局提示词库插件。所有 Agent 对话共用同一个侧边栏页面，用胶囊卡片管理常用提示词，支持一键复制、一键发送给当前 Agent，并由 Agent 在对话中辅助增删改查。

定位是一份"配置即资产"的提示词库：词条是用户亲眼可见、可手动编辑、可进版本库的 Markdown 文件，插件不锁死数据，哪天卸载插件，词条依然完好。

## 2. 目标与非目标

### 目标

- **widget 侧边栏**形态，跟随 Hana 平台主题。插件图标出现在 Hana 顶边栏书桌 UI 图标左侧，与其他侧边栏插件按默认排序出现（宿主行为）
- 二级结构：目录 → 词条，UI 呈现为可收纳胶囊列表，**目录支持折叠**
- 拖动自定义排序，顺序持久化且损坏时可自愈
- 双击复制；右键菜单**对齐 Hana 原生工作台文件操作**（功能对齐、样式美化统一），但**菜单项排序与插件独有功能（编辑、发送给当前 Agent）按本设计执行**；保留「编辑」和「以提示词方式发送给当前 Agent」
- **词条 = 文件**，经 UI 美化展示，胶囊标题不引入文件名后缀
- 「编辑」在 **Hana 默认预览栏展开 md 文件**并支持编辑，走正常文件编辑保存方式
- Agent 通过工具访问并辅助管理词条库
- 写入路径对截断、损坏、崩溃具备防御性

### 非目标（初始版本不做）

- 模板变量占位符填写（词条内 `{变量}` 保留原样复制）
- 三级以上目录
- 导入导出、云同步、多用户
- 词条标签系统（frontmatter 可预留，不实现 UI）
- page 全屏管理页（第一版取消，后续按需恢复）

## 3. 架构总览

```
┌─ UI 层（iframe，React + @hana/plugin-components，跟随平台主题）─┐
│  widget 侧栏（唯一形态）                                         │
│  胶囊列表：目录(一级) → 词条(二级)，目录可折叠                    │
│  交互：单击展开/收缩、双击复制、右键菜单、拖动排序                 │
│  「编辑」→ 调 Hana 默认预览栏打开该 md 文件编辑                    │
│  警告条：解析/写入失败时顶部渲染（React 组件，不用 alert）         │
└──────────────────────────┬──────────────────────────────────────┘
                           │ 只读写内存数组
┌──────────────────────────▼──────────────────────────────────────┐
│  逻辑层（server 侧：routes + tools + 生命周期，Node 运行时）       │
│  内存数组 = 真相源（启动时加载，UI 只认内存）                       │
│  原子写（tmp + rename）→ 写时备份 → onunload 尽力 flush            │
│  500ms 防抖合并连续拖动的写盘（仅拖动走防抖）                       │
└──────────────────────────┬──────────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────────┐
│  磁盘层（用户初始化时指定的数据目录）                               │
│  文件夹 = 二级目录，.md 文件 = 词条                               │
│  .order.json 主索引 + .order.json.bak 备份                        │
│  三级 fallback：主索引 → 备份 → mtime 时间排序                     │
└─────────────────────────────────────────────────────────────────┘
```

三条原则贯穿：

1. **文件系统即数据**：md 文件和文件夹是资产本体，UI 只是视图
2. **内存为真相**：UI 永远只读内存数组，磁盘是投影
3. **磁盘是投影**：投影损坏最多丢排序，词条正文一个字节不损

## 4. 数据模型

### 4.1 目录结构

```
<数据目录>/            ← 用户初始化时指定（写入插件配置 ctx.config.dataDir）
├── 写作/              ← 次级目录 = 一个文件夹（UI 右键目录可新建/删除）
│   ├── 文献综述提示词.md
│   └── 论文润色.md
├── 实验/
│   └── 转录组分析.md
└── .order.json        ← 排序索引（主）
    .order.json.bak    ← 排序索引（备份）
```

### 4.2 词条文件格式

```markdown
---
title: 文献综述提示词
created: 2026-08-15
---

你是海洋生物学专家，请按以下结构分析文献……
```

- `title`：胶囊显示名。**缺失时自动取正文内容前三个 token**（实现时取正文前几个自然词/字符）；胶囊显示自适应 UI 宽度与字号，**超出部分自动隐去**（省略号），不引入文件名后缀
- `created`：创建时间
- 正文：提示词内容（就是复制/发送时用的文本）
- frontmatter 可预留扩展字段（如 `tags`），初始版本 UI 不展示
- **编辑方式**：词条编辑走正常文件编辑保存流程，即「编辑」→ Hana 默认预览栏打开该 md 文件 → 用户在原生编辑器里改 → 保存即写盘。插件不提供自定义内联编辑器

**内存数组范围**：启动加载时把每个词条的 title + 正文全文读入内存（词条库规模小，一次性加载可接受），UI 展开卡片零延迟，Agent 工具的搜索/读取也直接走内存。磁盘仍是唯一持久层，内存每次启动重建。

### 4.3 排序索引格式（.order.json）

```json
{
  "version": 1,
  "directories": [
    {
      "name": "写作",
      "items": ["文献综述提示词.md", "论文润色.md"]
    },
    {
      "name": "实验",
      "items": ["转录组分析.md"]
    }
  ]
}
```

- 目录顺序 = `directories` 数组顺序；词条顺序 = `items` 数组顺序
- 磁盘上存在但索引缺失的词条/目录：UI 显示时按 mtime 补在对应位置尾部，下次写盘时并入索引
- 词条文件名自由命名，顺序与文件名无关

### 4.4 配置（manifest contributes.configuration）

- `dataDir`：数据目录绝对路径，初始化引导时写入，之后 UI 与工具只读此配置

## 5. 数据流

### 5.1 启动加载

1. 插件 onload：读配置取 `dataDir`
2. 读 `.order.json` 主索引 → 失败读 `.bak` → 再失败扫描磁盘按 mtime 排序
3. 任一 fallback 生效：构建内存数组，并标记"索引异常"，UI 顶部渲染警告条 + 「重建索引」按钮
4. **重建索引**：扫描磁盘重建内存数组 → 按规范重新写盘（原子写）→ **错误文件不删除，改名保留**为 `.order.json.corrupt-<时间戳>`，供人工/Agent 检查

### 5.2 拖动排序（UI）

1. 拖动落点判定（见 7.4）
2. 只改内存数组，UI 即时响应
3. 防抖 500ms（连续拖动重置计时，停止后开始计时）
4. 到期后原子写主索引 → 成功后复制为 `.bak`

### 5.3 词条编辑（Hana 预览栏 / Agent 工具共用）

1. UI 侧：「编辑」→ Hana 预览栏打开 md → 用户原生编辑保存（宿主写盘）
2. Agent 工具侧：`update_prompt` 调用 → 修改内存数组 → **立即原子写**对应 `.md` 文件（tmp + rename，同索引标准）
3. 写失败：保留内存状态，警告条提示，下次写盘自动重试

**写盘时机总规则**：仅「拖动排序」走 500ms 防抖；新建、删除、移动、编辑保存均为显式动作，立即写盘。删除词条/目录在用户确认后立即执行（删除 = 删 md + 更新索引一并原子完成）。

### 5.4 跨目录拖动（移动词条）

1. 同盘 `rename`（文件系统层面原子），目录不存在时报错提示
2. 目标目录已有同名文件：拒绝移动，toast 提示重名
3. 更新内存数组 + 索引路径 + 写盘
4. 动作链路：动作 → 内存 → rename → 写索引

### 5.5 Agent 工具写入

1. 工具调用 → server 侧同一套原子写路径
2. 写盘后广播插件内事件（bus.emit）
3. UI 在打开/聚焦 widget 时重载索引，保证两边一致

## 6. 健壮性设计

用户经历过磁盘级损坏，写入路径按"不会二次伤害数据"标准设计：

| 机制 | 说明 |
|------|------|
| 原子写 | 所有写盘（索引、词条、备份）一律 tmp + rename，杜绝半截文件 |
| 写时备份 | 主索引**成功写入后**复制为 `.bak`。不在启动时更新备份（避免把损坏的主索引复制成备份） |
| 三级 fallback | 主索引解析失败 → 读备份 → 备份也失败 → mtime 排序，词条无损 |
| 错误文件保留 | 重建索引时把损坏的原索引改名保留为 `.corrupt-<时间戳>`，不删除；数据可能仍在，留给人工或 Agent 检查重构 |
| Agent 修复通道 | 提供「重构排序索引」工具，Agent 可在对话中读取损坏文件、修复数据并重建索引（见第 8 节） |
| 内存真相源 | 磁盘写失败不影响 UI 一致性与内存状态；保留内存 + 警告条 + 下次重试 |
| 500ms 防抖 | 仅拖动停止后才写盘，一次操作一次写入，无写入风暴 |
| onunload flush | Hana 退出时尽力完成待写队列（原子写毫秒级，1s 内完成，不滞留） |
| 警告条 | 解析/写入失败在 UI 顶部渲染 React 提示条（不用 alert），含「重建索引」动作 |
| 校验范围 | 索引校验：JSON 可解析 + 结构合法（directories 数组、items 字符串数组），不做过度的内容校验 |

错误边界：最坏情况 = 丢一次排序 + 警告提示；词条正文、插件可用性、系统稳定性均不受影响。

## 7. UI 设计

### 7.1 形态与主题

- 仅 **widget**（右侧 Jian 侧栏，titlebar 按钮开关）。图标在顶边栏书桌 UI 图标左侧出现，与其他侧边栏插件按默认排序（宿主行为）
- `HanaThemeProvider mode="inherit"` + `@hana/plugin-components`，完全跟随平台主题
- 无自定义配色、无自定义字体

### 7.2 胶囊交互（词条）

- 默认状态：胶囊（圆角条，显示 title，自适应宽度，超出隐去）
- 单击胶囊：展开为卡片（显示正文预览）
- 展开态右上角：关闭横杠（×）按钮
- 单击标题栏：收缩回胶囊（与展开态右上角关闭横杠等效，两个入口同一功能）
- 双击：复制正文到剪贴板 + toast「已复制」
- 目录行：支持折叠/展开整目录
- 右键词条：菜单（见 7.3），对齐 Hana 原生工作台文件操作

### 7.3 右键菜单

**词条菜单**（顺序固定）：

1. 编辑 → Hana 默认工作台预览栏打开该 md 文件（原生编辑保存）
2. 复制 → 复制正文（与双击同路径）
3. 发送给当前 Agent → 插件 route 通过 session API 定位当前会话，把正文作为用户消息发送
4. 用默认应用打开（对齐原生文件操作）
5. 复制路径（Hana 默认方式）
6. 截图分享（Hana 默认方式）
7. --- 分隔线
8. 删除 → 确认后删除 md 文件 + 更新索引（删除前二次确认）
9. 重命名（改名后同步更新索引）

**目录菜单**（顺序固定）：

1. 新建目录（次级目录，输入名称 → mkdir）
2. 新建卡片（输入标题与内容 → 写新 md + 并入索引，**自动生成默认 frontmatter 格式**）
3. 复制路径（Hana 默认方式）
4. --- 分隔线
5. 删除目录 → **目录非空时拒绝**（提示先清空词条），安全默认
6. 重命名（目录改名 → rename 文件夹 + 同步更新索引中的目录名）

> 注：菜单项「用默认应用打开 / 截图分享 / 复制路径 / 重命名」对齐 Hana 原生工作台文件操作；具体宿主能力映射（能否直接调宿主原生菜单或需插件侧模拟）在实现阶段确认，行为与原生一致为原则。

### 7.4 拖动规则

| 落点 | 行为 |
|------|------|
| 同目录词条之间 | 重排（只改内存 + 索引） |
| 另一目录的标题上 | 移动到该目录（rename + 更新索引 + 插入目标目录尾部） |
| 目录行拖动 | 重排目录顺序 |
| **拖拽词条到会话区** | 以 Hana 默认拖拽方式，将**文件路径**发送给当前 Agent（不显示可点击 UI） |
| **拖拽词条到别的目录** | rename：动作 → 内存 → rename → 写索引 |
| 空白处 | 无操作，松手弹回原位 |
| 目标目录已有同名文件 | 拒绝，toast 提示重名 |

拖动只改变内存，写盘走 5.2 的防抖流程。

### 7.5 警告条

- 触发场景：索引解析失败、写盘失败、fallback 生效
- 渲染：侧栏顶部 React 提示条（主题组件 Alert 类），文案说明当前状态 + 可用的「重建索引」按钮
- 不用 `alert`、不用系统对话框

## 8. Agent 工具

六把工具，全部走 server 侧同一条原子写路径：

| 工具 | 作用 | sessionPermission |
|------|------|-------------------|
| `search_prompts(query?)` | 按关键词搜词条名+正文，返回目录/名字/摘要 | `readOnly: true` |
| `read_prompt(path)` | 读单个词条全文 | `readOnly: true` |
| `create_prompt(directory, name, content)` | 新建词条；目录不存在自动 mkdir；重名报错；自动生成默认 frontmatter | `external_side_effect`（送审） |
| `update_prompt(path, content)` | 修改正文 | `external_side_effect`（送审） |
| `delete_prompt(path)` | 删除词条 | `external_side_effect`（送审） |
| `rebuild_order_index(keep_corrupt=true)` | 重构排序索引：扫描磁盘重建 + 原子写 + 保留损坏原文件 | `external_side_effect`（送审） |

- 目录管理不单独做工具：`create_prompt` 的 directory 参数覆盖（不存在则建）
- `rebuild_order_index` 供 Agent 在索引损坏但数据完好时辅助重构（配合 `.corrupt-*` 保留文件可做数据抢救）
- 写工具声明 `resource.write`，读工具声明 `resource.read`；数据目录访问经 `ctx.resources`
- 工具写盘后广播事件，UI 聚焦时重载索引

## 9. Manifest 草案

```json
{
  "id": "prompt-shelf",
  "name": "PromptShelf",
  "version": "0.1.0",
  "description": "个人提示词库：侧边栏胶囊管理，双击复制，右键编辑/发送给当前 Agent",
  "trust": "full-access",
  "capabilities": ["resource.read", "resource.write", "session"],
  "contributes": {
    "configuration": {
      "properties": {
        "dataDir": { "type": "string", "title": "提示词库数据目录" }
      }
    },
    "widget": {
      "title": { "zh": "提示词架", "en": "PromptShelf" },
      "icon": "<svg viewBox='0 0 24 24'><path fill='currentColor' d='...'/></svg>",
      "route": "/shelf"
    }
  },
  "ui": {
    "hostCapabilities": ["clipboard.writeText", "resource.pick", "resource.open"]
  }
}
```

- `resource.pick`：初始化引导时用 `hana.resources.pick()` 选择数据目录
- `resource.open`：「编辑」在 Hana 预览栏打开 md 文件
- `clipboard.writeText`：双击复制 / 复制路径
- `toast.show` 免授权，无需声明
- 无 page 声明（第一版取消全屏页）

## 10. 初始化流程

1. 插件首次打开 widget
2. 检测配置无 `dataDir` → 渲染引导页
3. 用户经 `hana.resources.pick()` 选择目录（或手动输入路径）
4. 校验目录可读写 → 写入配置 → 扫描建索引 → 进入正常界面
5. 目录为空时：自动创建 `.order.json` 空索引，提示先新建目录

## 11. 测试策略

- **dev loop**：`plugin.dev.install` → 修改 → `plugin.dev.reload` → `plugin.dev.invokeTool` smoke test → `plugin.dev.diagnostics`
- **manifest.dev.scenarios**：声明第一阶段的工具 smoke test（create → search → read → update → delete → rebuild 闭环）
- **手动场景**：拖动排序 → 重开 widget 验证顺序保持；手动损坏 `.order.json` → 验证 fallback 到备份；同时损坏主+备 → 验证 mtime 排序 + 警告条 + 重建索引 + `.corrupt-*` 保留
- **写入路径单测**（如可行）：原子写、防抖、备份更新时机、损坏文件改名保留

1. 脚手架（professional-react 模板 + full kind）+ manifest 骨架（无 page）

## 13. 范围外清单（YAGNI）

- 变量占位符填写弹窗（词条 `{变量}` 原样复制）
- 标签系统 UI（frontmatter 预留字段，不实现）
- 三级以上目录、目录嵌套
- 导入导出、云同步、多设备
- 多用户/共享词条库
- 词条历史版本、回收站
- page 全屏管理页（第一版）

## 14. 开放问题

- 「发送给当前 Agent」定位当前会话的精确 API 需在实现阶段从 PLUGINS.md / plugin-runtime 源码确认（行为已定：把词条正文作为用户消息发送到当前会话）
- 「编辑」打开 Hana 预览栏的精确调用（`hana.resources.open` 的 local-file 形态与编辑模式）需实现阶段确认
- 原生对齐菜单项（用默认应用打开 / 截图分享 / 重命名）的宿主能力映射需实现阶段确认，原则是行为与 Hana 原生文件操作一致
- title 缺省时"前三个 token"的切分规则（按空格/按中文标点/按字符）在实现时定一个稳定规则
